These are **client-side models**: a player who does not have the file cannot see
them, and the engine will try to download them. Until the download path is
proven (fastdl mirror or direct download - see `docs/WINTERFEST.md` §1.1), they
stay here unreferenced.

The cosmetic registry in `winterfest.ini` addresses them by id
(`hat_xmas_red`, ...) so enabling them later is a config change, not a code
change.
